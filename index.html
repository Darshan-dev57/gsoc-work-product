Goals

I spent the program making the checker handle the Java people actually write, then fixing whatever that work exposed. Over the summer I opened 19 pull requests across three repositories: JPF-Core (12), JPF-NAS (5), and jpf-nhandler (2). 18 are merged and 1 is open for review.

Abstract

Java Pathfinder finds bugs by running a program down every path it could take. But it was built for older Java, and modern code broke that promise: sealed classes and records, plus the hidden setup calls the compiler generates for them, either crashed the checker or silently gave wrong answers. My project brings the checker up to modern Java. I completed sealed-class and record support in the core engine, fixed the text-building and switch machinery around them, and repaired the networking and delegation extensions that work touched. Every fix ships with a test that fails before and passes after, so future contributors build on verified ground.

Feature areas

  • Sealed classes. Read the permitted-subclass list correctly and reject classes that break the seal.
  • Records. Understand record data and run the equality, printing, and hashing code the compiler generates.
  • Pattern-matching switch. Run the type and enum switches Java 17 added.
  • String concatenation. Handle the constants and boxed values modern text building emits.
  • JDK models. Fill the startup hooks and file models Java needs before checking starts.
  • Test infrastructure. Isolation between tests and control over when a run counts as finished.

Validation

How each change was proven before review.

  • Build first. Every fix starts from a green build plus a HelloWorld run, so failures reproduce against a known-good baseline.
  • Fail before, pass after. Each new test runs against the unfixed code to confirm it catches the bug, then against the fix.
  • Full suite. Risky edits end with full runs: 1028, 1066, and 1071 tests recorded green across these pull requests.
  • Small pull requests. Combined work was split per reviewer feedback, so each change is independently reviewable.

What Remains

Impact and results

  • Modern Java support. JPF analyzes programs using records, sealed classes, pattern switch, and modern text building.
  • Working demos. The socket dialogue and jar delegation examples run instead of crashing.
  • Green suites. Previously failing tests pass: serialization, sockets, delegation, and the full core suite.
  • Cleaner builds. Simpler scripts and isolated tests make future contributions easier to verify.

Challenges and solutions

Silent name mismatches.Slash-notation names never equaled dot-notation names, so sealed checks failed quietly. Solved by normalizing at storage with the same helper interfaces already used.
Bootstrap complexity.JVM setup calls hide in classfile attributes. Solved by giving each bootstrap family its own dispatch branch and measuring host behavior first.
Large combined changes.My networking changes arrived as one large pull request, and the reviewers asked me to split it. I divided the work into build, formatting, cleanup, and peer fixes, and each piece merged faster than the bundle ever would have.

Remaining work

  • Work through the remaining Java 17 gaps after the program.
